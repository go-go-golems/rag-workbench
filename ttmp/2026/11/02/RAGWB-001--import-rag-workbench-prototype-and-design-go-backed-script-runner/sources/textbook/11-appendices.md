# Appendices

Reference material for the whole book: the API, the presets, the data formats and the terms.

## A. API reference

This appendix lists every public name in `rag.js`, `gui.js`, `kit.js` and the agent's scope, generated by enumerating the loaded modules and reading the defaults from the source (`rag.version` is `0.1.0`). Signatures use the library's own argument names. A parameter written `name = v` has default `v`; "λ" marks a parameter that may be a stored lambda. Pipelines are built from specs (chapter 7), compiled to an IR (chapter 10), built and run by an engine (chapters 11–12), changed through a workspace (chapters 21–23) and shown through `gui` (chapters 24–26).

Component factories are generated from the registry: `rag.source.files`, `rag.parse.markdown`, `rag.chunk.sections`, `rag.index.bm25`, `rag.index.terms`, `rag.enrich.llm`, and so on for every type, plus the short names `rag.files`, `rag.markdown`, `rag.sections`, `rag.bm25` and `rag.terms`. A factory returns a component reference `{ $c, p }` that builder methods accept.

### A.2 Corpus builder (`CorpusSpec`)

Every method returns a new frozen spec. The builder keeps a cursor of the latest `files`, `docs` and `chunks` node so the next call can wire itself.

| Method | Adds | Default id | Wiring |
| --- | --- | --- | --- |
| `.from(src)` | `source.files` (string or `{ glob }`) or `source.inline` (array of `{ name, text }`) | `files` | no inputs |
| `.parse(parser = rag.markdown())` | `parse.markdown` | `parse` | latest files |
| `.chunk(spec)` | `chunk.sections` or another chunker | `chunks`, then `chunks_2`… | latest docs; becomes the chunk cursor |
| `.chunk(name, (doc, ctx, p) => chunks, opts)` | `chunk` with a build lambda | slug of `name` | latest docs, or `opts.from`; a named stream after the first does not move the cursor |
| `.enrich(name, (chunk, ctx, p) => value, opts)` | `enrich` | `enrich_<name>` | latest chunks, or `opts.from`; options `concurrency = 3`, `budget: { calls }` |
| `.enrich(name, rag.enrich.llm(opts), { from })` | `enrich.llm` | `enrich_<name>` | moves the cursor only when it reads the current chunk stream |
| `.index(name, rag.bm25(p) or rag.terms(p), { from })` | `index.bm25` or `index.terms` with `p.name = name` | `ix-<name>` | latest chunks, or `from` |
| `.synonyms(table or rag.bake(…))` | `synonyms` | `synonyms` | latest docs |
| `.then(component, { id, from })` | any build component | type's last segment | the cursor of the component's first input port |
| `.use(fragment, params)` | whatever the fragment adds |  |  |
| `.as(id)` | renames the spec |  |  |
| `.toJSON()` | `{ kind: 'corpus', id, nodes }` |  |  |

### A.3 Plan builder (`PlanSpec`)

| Method | Effect |
| --- | --- |
| `.over(corpus)` | Attaches a corpus; its nodes are compiled into the same IR. |
| `.signals(obj)` | Declares signals and their initial values. Declaring `q` makes it the query cursor. |
| `.<family>(…)`, `.<family>.<variant>(…)` | Adds a live node of that type. Generated from the registry as prototype getters, so components defined later appear on existing plans. |
| `.then(component, opts)` | Adds any live component. |
| `.patch(ops)` | Records ops applied after compilation (chapter 21). |
| `.variant(id, ops or (plan => plan))` | A renamed copy, patched or transformed. |
| `.use(fragment, params)` | Applies a fragment. |
| `.as(id)` | Renames the plan. |
| `.toJSON()` | `{ kind: 'plan', id, signals, nodes, ops }` |

Every live step accepts `{ id, trigger: 'change' or 'submit', from }` in its options. Without `from`, a node reads the cursor of each input port. A retrieve adds a parallel hit stream; any step that takes a single `hits` input while two or more streams are open throws `needs a fuse step first, e.g. .fuse.rrf()`. Default ids come from the component (`retrieve` uses the index name, `fuse.*` uses `fuse`, `filter.where` uses `filter`, `rerank.llm` uses `rerank`, `expand.neighbors` uses `neighbors`, `expand.links` uses `links`), with `_2`, `_3` appended on collision.

### A.4 Graph form and fragments

`rag.graph(id, g => { … })` exposes four calls: `g.over(corpus)`, `g.signal(name, value)` returning a handle, `g.node(id, component, { from })` returning a handle, and `g.output(name, handle)`, which pins an output. `from` takes handles or ids, and the node is wired exactly as stated. A fragment is `rag.fragment(id, (spec, params) => spec)`; `spec.use(fragment, params)` calls it, and it works on corpus and plan specs alike.

### A.5 Build components

Build components run once per digest (chapter 11). `map` components run per item with a per-item cache; the rest run once over all inputs.

| Type | Ports | Parameters (defaults) | Notes |
| --- | --- | --- | --- |
| `source.files` | → files | `glob = '*'` (case-insensitive, `*` only) | Its digest includes every file's content hash. |
| `source.inline` | → files | `files` |  |
| `parse.markdown` | files → docs | `frontmatter` (set `false` to skip) | Map. Blocks: paragraph, list, fence, table, callout, quote. |
| `chunk.sections` | docs → chunks | `depth = 3`, `maxTokens = 450`, `minTokens = 30`, `prefixHeading`, `overlap` (tokens), `dropMermaid = true` | Map. Fences and tables stay whole up to 3 × `maxTokens`. |
| `chunk` | docs → chunks | `fn` λ `(doc, ctx, p) => [{ headingPath, text, blocks?, … }]` | Map. Chunk kind is the node id. |
| `enrich` | chunks → chunks | `name`, `fn` λ `(chunk, ctx, p) => value`, `concurrency = 3`, `budget.calls` | Map, async, per-item cache in memory and in `env.cache`. Costs calls if the lambda mentions `sample`. |
| `enrich.llm` | chunks → chunks | `name`, `prompt` (summary, questions, keywords), `tier = 'quick'`, `concurrency = 3`, `budget.calls` | One `sample.json` call per chunk. Deferred when `buildCalls` is `'explicit'`. |
| `index.bm25` | chunks → index | `fields = { title: 2, headingPath: 3, text: 1 }`, `k1 = 1.2`, `b = 0.75`, `stem = true`, `name` | Field values may be dotted paths into the chunk. |
| `index.terms` | chunks → index | `keys = ['type', 'tags', 'status']`, `name` | Matches whole metadata values that appear in the query; score `1 / ln(2 + n/10)`. |
| `synonyms` | docs → value | `table` (object or bake) | Applied at search time to every `index.bm25` retrieve, at weight 0.5. |
| `bake` | docs → value | `value` (bake) |  |

### A.6 Live components

Live components run per query. Trigger is the default; any node can override it. "Skipped" is what the node outputs when the trigger excludes it: `pass` returns its input unchanged, `null` returns nothing.

| Type | Ports | Trigger | Reads | Parameters (defaults) | Skipped |
| --- | --- | --- | --- | --- | --- |
| `retrieve` | queries → hits | change |  | `index`, `k = 20`, `perQuery = true`; or `fn` λ `(s, ctx, queries, p) => hits` | input |
| `rewrite` | queries → queries | change |  | `fn` λ `(s, ctx, queries, p) => queries` | pass |
| `rewrite.llm` | queries → queries | submit | `q` | `n = 3`, `tier = 'quick'` | pass |
| `fuse.rrf` | hits\* → hits | change |  | `k = 60`, `weights = {}` (by input id), `limit = 60` | input |
| `fuse.max` | hits\* → hits | change |  | none | input |
| `filter` | hits → hits | change |  | `fn` λ `(s, ctx, hit, p) => bool` | input |
| `filter.where` | hits → hits | change | `filters` | `key = 'filters'` | input |
| `rerank` | hits → hits | change |  | `fn` λ `(s, ctx, hits, p) => hits` | pass |
| `rerank.llm` | hits → hits | submit | `q`, `k` | `top = 20`, `keep = s.k or 8`, `tier = 'quick'` | pass |
| `limit` | hits → hits | change |  | `k = s.k or 8` (number or λ) | input |
| `expand.neighbors` | hits → hits | change |  | `before = 0`, `after = 1`, `top = 5`, `maxChars = 6000`, `decay = 0.5` | input |
| `expand.links` | hits → hits | change | `q` | `index`, `top = 5`, `max = 4`, `decay = 0.5` | input |
| `pack` | hits → context | change |  | `budget = 40000` (characters), `order = 'rank'` or `'doc'`, `maxPerDoc = 6` | input |
| `answer` | context → answer | submit | `q` | `instructions`, `tier = 'default'` | null |
| `agentic` | queries → answer | submit | `q` | `indexes`, `maxReads = 8`, `instructions`, `tier = 'default'` | null |
| `map` | inType → outType | change |  | `fn` λ `(s, ctx, input, p)`, `inType = 'hits'`, `outType = 'hits'` | input |

A lambda in a non-lambda parameter (for example `limit(s => s.k)`) is evaluated per run with `(s, ctx)` and its signal reads are recorded. The static scan also adds signals read by any lambda to the node's `reads`.

`rag.define(type, def)` registers a component. `type` must look like `family` or `family.variant`. `def` takes `phase` (`'build'` or `'live'`, required), `in` (default `hits` for live, `docs` for build), `out` (default `hits` or `chunks`), `params` (defaults), `trigger`, `id`, and either `run(s, ctx, input, p)` for live or `map(item, ctx, p)` or `all(inputs, ctx, p)` for build. A build `map` that outputs chunks may return plain `{ headingPath, text }` objects; ids are assigned for it.

### A.7 Lambda contexts

Lambdas are stored as source and run closed: a name that is neither an argument nor an allowed global throws `references free identifier` on first run (chapter 9). These are the arguments each kind receives.

| Kind | Arguments | `ctx` members |
| --- | --- | --- |
| Build slot (`chunk`, `enrich`, custom `map`) | `(item, ctx, p)` | `node`, `item`, `sample`, `sample.json`, `tokens`, `slug`, `hash`, `clip`, `log`, `files()`, `docs`, `chunks` |
| Bake | `(ctx)` | `docs`, `chunks`, `tokens`, `slug` |
| Live slot (`filter`, `rerank`, `rewrite`, `retrieve`, `map`, custom `run`) | `(s, ctx, input, p)` (`filter` gets one hit) | `node`, `sample`, `sample.json`, `signal` (abort), `signals`, `synonyms`, `tokens`, `clip`, `index(name)`, `indexNames()`, `firstIndex(kind)`, `chunk(id)`, `chunks(f)`, `doc(id)`, `docs()`, `links(docId)`, `neighbors(id, { before = 1, after = 1 })`, `log`, `note(text)`, `emit(text)` |
| Live parameter (for example `limit(s => s.k)`) | `(s, ctx)` | as for a live slot |
| Judge | `(s, { sample }, { q, answer, evidence })` | `sample` only |

Hits passed to `filter` and `rerank` lambdas are expanded with `docId`, `title`, `headingPath`, `text`, `meta`, `kind` and `tokens`. A `rerank` lambda may return hit objects or bare ids; ids get score `1 / rank`.

## B. Preset catalogue

## C. Formats

Every object in this appendix was printed by running the library in node on the bundled corpus. The examples use one small plan throughout:

```js
const corpus = rag.corpus('reports').from(rag.files('*.md')).parse(rag.markdown())
  .chunk(rag.sections({ depth: 3, maxTokens: 450 }))
  .index('text', rag.bm25({ fields: { title: 2, headingPath: 3, text: 1 } }))
  .index('meta', rag.terms({ keys: ['type', 'tags'] }));
const plan = rag.plan('small').over(corpus).signals({ q: '', k: 5 })
  .retrieve('text', { k: 20 }).retrieve('meta').fuse.rrf({ k: 60 })
  .limit(s => s.k).pack({ budget: 8000 }).answer();
```

Long chunk ids are shortened to `cv#11-why-chatgpt-still-showed-no-actions`, where `cv` stands for `project-report-coinvault-mcp-from-local-conformance-to-chatgpt-2`. The answer text comes from a stand-in for Claude.

### C.2 Operations

Ops are plain objects applied in order by `ws.apply`, `rag.applyOps` or `plan.patch`. A batch is atomic: the first failing op throws `op N (kind): message` and nothing changes. After the batch the IR is recompiled, so an op list that leaves the graph invalid throws `after ops: …`.

| Op | Shape | Effect |
| --- | --- | --- |
| `set` | `{ op: 'set', node, path, value }` | Sets a param; `path` is dotted (`fields.title`). Functions become lambdas. |
| `unset` | `{ op: 'unset', node, path }` | Removes a param. |
| `insert` | `{ op: 'insert', node: { t, p, trigger? } or component, id?, after or before or in, only?, feeds? }` | Adds a node. `after` rewires that node's consumers (or only those in `only`) and moves outputs of the same type; `before` takes over a single-input node's input; `in` wires explicitly and `feeds` appends it to other nodes' inputs. |
| `remove` | `{ op: 'remove', node }` | Deletes a node and rewires consumers to its input. Refused while another node `uses` it, or when a consumer cannot be rewired. |
| `replace` | `{ op: 'replace', node, with: { t, p, trigger? } }` or `{ op: 'replace', node, fn, param = 'fn' }` | Swaps the component, or only a lambda. |
| `wire` | `{ op: 'wire', node, in: [ids] }` | Sets a node's inputs. |
| `signal` | `{ op: 'signal', key, value }` | Adds or changes a signal's initial value. |
| `trigger` | `{ op: 'trigger', node, value: 'change' or 'submit' }` | Overrides a node's trigger. |
| `output` | `{ op: 'output', node, name }` | Pins a named output. |
| `rename` | `{ op: 'rename', node, to }` | Renames a node and every reference to it. |

Real refusals from the example workspace:

```text
op 1 (set): no node 'nope'. Nodes: files, parse, chunks, ix-text, text, limit
after ops: 1 problem:
  fuse: input 'q' gives signal but this port takes hits
```

The second is `remove meta` on the fused plan: removing one of two retrievers rewires the query signal into `fuse`, which the checker rejects, so the edit needs a `wire` op as well.

| Chunk field | Meaning |
| --- | --- |
| `id` | `docId#slug-of-last-heading`, with the chunk kind inserted for non-section streams and `-2`, `-3` on collisions. |
| `kind` | `section`, or the node id of a lambda chunker. |
| `meta` | The document's frontmatter, minus title, dates, source paths, related notes and strings over 120 characters. |
| `callout`, `hasCode`, `hasTable` | Derived from the chunk's blocks. |
| `tokens` | Estimated tokens. |
| `part`, `parts` | Position when a section was split by `maxTokens`. |
| `ord` | Position in the stream. |

A document from `parse.markdown` is `{ id, name, title, meta, h1, sections, links }`. Each section is `{ level, title, path, blocks, id, text }`, with `level` 0 for text before the first heading; a block is `{ kind, text }` plus `lang` (fence), `header` and `rows` (table), or `variant` (callout). `links` lists `[[wiki link]]` targets.

### C.8 The gui IR

`app.compile()` for a three-component app:

```js
gui.app('mini').title('Mini search').use(plan).state({ selected: null }).derive('n', s => (s.out.limit || []).length)
  .view(v => v.col(c => c.searchBox('q', { placeholder: 'Ask…' })
    .results({ onSelect: (s, ctx, h) => ctx.set({ selected: h.id }) }).chunk(s => s.selected)));
```


| Field | Meaning |
| --- | --- |
| `state` | Initial state, JSON-copied. A bound app adds the plan's signals and `out`, `run`, `stream`, `result` at mount. |
| `derived` | Lambdas recomputed after every state change, up to four passes until stable. |
| `watchers` | `{ key, fn }`: handlers called when a key changes. |
| `uses` | The plan id the app binds to, or `null`. |
| `root` | The view tree. Node ids `n1`, `n2`… are assigned in build order; containers carry children in `c`. |
| `p` | Props: values, or lambdas `{ $fn }`. Handler props (`onClick`, `onSelect`, `onRowClick`, `onCite`, `onSubmit`, `item`, canvas `draw`) are called with extra arguments rather than evaluated for a value. |

## D. Glossary

Terms as this book uses them, in alphabetical order. The chapter column gives where the term is defined; Appendix A and C give the exact API and formats.

| Term | Definition | Chapter |
| --- | --- | --- |
| Agent | Claude with one `eval` tool that runs JavaScript in the page against `rag`, `gui`, `wb`, `ws`, `ui`, `chat` and `ref`. | 28 |
| Agentic node | A live `agentic` node that gives Claude `search`, `read`, `outline` and `documents` tools and produces an answer with evidence labels assigned on read. | 17 |
| `answerHas` | A golden-case pattern that the answer text must match; scored 0 or 1 when the run produced an answer. | 20 |
| App (gui) | A compiled `gui` description: state, derived values, watchers, the plan it uses, and a view tree built once. | 24 |
| Artifact edge | An IR edge from a build output, such as an index, to the live node that uses it. | 10 |
| Atomic block | A fence or table that the section chunker keeps whole up to three times `maxTokens`. | 4 |
| Bake | `rag.bake(ctx => value)`: a lambda evaluated once at build time over the built docs and chunks, whose result becomes a parameter value. | 9 |
| BM25 | The lexical score used by `index.bm25`: inverse document frequency times saturated term frequency with length normalization, summed over query terms; `k1 = 1.2`, `b = 0.75`. | 5 |
| BM25F field weights | Per-field multipliers (`title: 2`, `headingPath: 3`, …) applied to term counts before scoring. | 5 |
| Branch | A child workspace created at the parent's revision; merged by replaying its ops, refused if the parent has moved. | 23 |
| Build memo | The engine's map from build-node digest to output; a digest found there is reused without running the node. | 11 |
| Build phase | The phase in which source, parse, chunk, enrich, index and bake nodes run, once per digest. | 11 |
| Build slot | A lambda parameter of a build component, run per item at build time, for example `.chunk('rows', (doc, ctx, p) => …)`. | 9 |
| Callout | A `> [!kind]` block, kept as its own block kind and indexed as the chunk field `callout`. | 3 |
| Chunk | The unit that is ranked, cited and scored: a slice of one document with an id, heading path, text, metadata and token count. | 4 |
| Chunk id | `docId#slug`, stable while the document and its headings are unchanged; used by fusion, expansion, selection and `explain`. | 4 |
| Closed lambda | A lambda run without its closure: only its arguments and a fixed set of globals are visible. | 9 |
| Component | A registered node type with a phase, typed ports, a default trigger and a run, map or all function. | 8 |
| Context | The output of `pack`: evidence-labelled text under a character budget, plus the evidence list. | 15 |
| Corpus spec | The immutable build-phase description produced by `rag.corpus(…)`. | 7 |
| Cursor | The builder's record of the latest node of each port type, used to wire the next call. | 7 |
| Deferred build | A build of a Claude-costing node with calls disallowed: items pass through unprocessed, the output is stored as partial, and `engine.pending` lists the node until Build runs it. | 11 |
| Digest | A hash of a build node's type, params, input digests and, for `source.files`, file contents; it names the node by what it would compute. | 10 |
| Dirty | A build node whose current digest has no memo entry. | 11 |
| Dry run | `ws.dryRun(ops)`: classifies the effect of ops without applying them. | 21 |
| Evidence label | `E1`, `E2`, …: the label `pack` or the agentic node gives each piece of context, cited inline by the answer. | 15 |
| Facet | A count of metadata values over a result set, written back as a filter signal when selected. | 6 |
| Family method | A plan method such as `.fuse.rrf()` generated from the registry; installed on the prototype, so later definitions appear on existing plans. | 8 |
| Fragment | `rag.fragment(id, (spec, params) => spec)`: a reusable spec transformation. | 7 |
| Free identifier | A name in a lambda that is neither an argument nor an allowed global; it throws on first run. | 9 |
| Fusion | Combining several hit lists into one; `fuse.rrf` by reciprocal rank, `fuse.max` by maximum score. | 14 |
| Golden case | A question with patterns for the document, section and optionally answer text that should answer it. | 18 |
| Graph form | `rag.graph`: a plan whose nodes, inputs and outputs are all stated explicitly. | 7 |
| Heading path | The list of headings above a section, joined with `›` for display and matching. | 3 |
| Hit | `{ id, score, via, … }`: a chunk at a position in one node's ranked list. | 13 |
| IR | The compiled graph: typed nodes in topological order, edges, signals, outputs and a digest. | 10 |
| Lambda | A function stored as source text, `{ $fn }`, so a pipeline can be saved and edited as data. | 9 |
| Live phase | The phase in which query nodes run on every search. | 11 |
| Live slot | A lambda parameter of a live component, run per query with signals, context and input. | 9 |
| Metric | hit@k, MRR, nDCG@k or recall@k, computed per case from the rank of relevant chunks. | 19 |
| Op | A data description of one IR edit; ten kinds. | 21 |
| Optimistic concurrency | Planning ops against a known revision and passing it as `expect`, so a stale plan is refused. | 22 |
| Output | A named IR entry (`hits`, `context`, `answer`, …) pointing at a node; derived unless pinned. | 10 |
| Partial output | A build output stored with deferred or skipped items; reused only while calls stay disallowed. | 11 |
| Per-item cache | The cache of map-component results keyed by component, params and item hash, in memory and in the database. | 11 |
| Plan spec | The immutable live-phase description produced by `rag.plan(…)`. | 7 |
| Port | A typed input or output of a component: files, docs, chunks, index, value, queries, hits, context, answer. | 8 |
| Preset | A pipeline script in the editor's picker that returns `{ plan, evals, app, variants }`. | 2 |
| Reads | The signals a node depends on, from the component's declaration, the static scan of its lambdas, and runtime tracking. | 9 |
| Receipt | What `ws.apply` returns: the new revision and the live, dirty, changed and removed nodes. | 22 |
| Relevant chunk | A chunk whose document and section match a golden case's patterns. | 18 |
| Revision | The workspace's change counter; it increases on every apply, undo, redo, reset and restore. | 22 |
| RRF | Reciprocal rank fusion: each list adds `weight / (k + rank)`; `k = 60` by default. | 14 |
| Section | The text under one heading, with its level, path and blocks. | 3 |
| Session | A runner bound to an engine and an IR that keeps a memo between runs. | 12 |
| Session memo | Per-node record of the last run's params, input identities and signal values read; a node whose record matches is reported `cached`. | 12 |
| Signal | A named input of a query run, such as `q`, `k` or `filters`; a node in the IR and a state key in a bound app. | 12 |
| Snapshot | `{ ir, revision, history, future }` saved before each agent step so the step can be reverted. | 23 |
| Spec | An immutable builder value; every builder call returns a new spec. | 7 |
| Status | A trace entry's outcome: ran, cached, skipped or error. | 12 |
| Sweep | Scoring a grid of `set` ops on the same evals; each configuration rebuilds only what it changed. | 20 |
| Synonyms table | A build-time value mapping phrases to expansions, applied to BM25 queries at weight 0.5. | 6 |
| Synthetic case | A golden case whose question Claude wrote for a sampled section. | 18 |
| Terms index | `index.terms`: matches whole metadata values (type, tags, …) that appear in the query. | 6 |
| Trace | One entry per live node per run: status, counts, time, calls and top hits. | 13 |
| Trigger | When a live node runs: `change` on every keystroke, `submit` only on Enter. | 12 |
| Variant | A plan derived by `plan.variant(id, ops)`; the original is unchanged. | 7 |
| Workspace | The holder of the current IR, its engine, revision and history, through which edits are applied. | 22 |
