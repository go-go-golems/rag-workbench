## System understanding

Application authors compose immutable corpus builders (source, parse, chunk, index) and live query plans (retrieve, fuse, filter, rerank, pack, answer). The compiler validates ports and dependencies and topologically orders nodes. Goja and browser execute the generated same bundle, with host-specific filesystem/index/record implementations. Goja work occurs on its owner; model/rerank operations do Go work outside that owner and post callbacks back.

A digest identifies a build output for particular inputs; a lineage identifies the same build step across input changes. Saved artifacts hold payloads; lazy wrappers defer opening/decoding them; native views expose synchronous record access. These terms must be distinguished from proposed dataset versions, published snapshots and resource leases.

Concrete path inspected: `examples/apps/reports/lib/corpus.js` creates Markdown chunks and text/meta indexes; `lib/plans.js` retrieves both and fuses rankings, or adds provider decisions/answers. `runner.OpenApp` builds once and keeps a Session. `Session.run` obtains `engine.artifacts`, may await a shared build, executes live nodes, and decorates the result with artifact-backed methods. Its events already consult the initially obtained artifacts. Embedded `__serve.run` subsequently calls current `art()` to package chunk bodies and neighbors. HTTP routes return JSON or use the SSE pump; the browser stores received chunks/docs/neighbors by bare ID.

## Underspecified decisions to expose

1. Snapshot slot identity must be distinguished from exact source/output version and full job key; otherwise querying last good data during refresh is ill-defined. Propose a stable plan/config slot plus immutable generation identity.
2. Concurrent refresh publication needs one per-slot arbiter or ordering rule. Propose serializing builds/publication for a slot, avoiding older candidates replacing newer generations.
3. Dataset source identity and content/version digest algorithm, deterministic iteration across delta/load, document-reference/order signatures need concrete types before migration.
4. Retention policy, stale-generation response shape/status, result/event byte limits and shutdown/join bounds require explicit values. Propose stale errors rather than implicit generation fallback; do not invent already accepted defaults.
5. Durable pointer update and in-memory publish must have one defined commit point and cancellation behavior. Crash testing and fsync support are platform-specific.
6. Registry duplicate adoption must specify ownership on success and failure. Propose reuse existing entry/close redundant opener; caller closes only on rejected adoption.
7. Cross-dataset canonicalization must be an ordinary explicit component/policy, not implicit ID union. Error when no such policy is supplied is simplest initial behavior.
8. General graph delete policy is not yet fixed; reject unresolved dependents by default, reserve special unconditional rewrite for explicit lexical export.
9. Outcome cancellation arbiter must freeze decisions before cleanup and have a precise concurrency ordering; merely calling Classify before cancel does not define competing real cancellation.
