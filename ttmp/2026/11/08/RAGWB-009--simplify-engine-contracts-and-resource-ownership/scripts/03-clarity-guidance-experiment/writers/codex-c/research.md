## System and representative flow

A corpus builder defines source → parse → chunks → indexes. A plan adds signal-driven retrieval, fusion, filters, optional provider reranking, evidence packing and answers. Immutable builder values compile to a validated, ordered graph. Engine builds/memoizes outputs, possibly loading lazy persistent records. Session executes live nodes and decorates results. Goja owns JS execution; Go bridges perform provider work off-owner and post callbacks back. Runner serves a long-lived app; HTTP exposes JSON/SSE and browser lookups.

Trace inspected: reports `lib/corpus.js` and `lib/plans.js`; `Session.run` acquires `engine.artifacts`, joins `buildShared` if missing, awaits components, then `decorateResult` captures `art`. `runner/serve.go` embedded `__serve.run` subsequently collects and calls current `art()` again to pack response. That later lookup is an independent generation hazard. Session catches node errors and records fallback outputs; cancellation breaks execution. `scope.ts` captures request scope synchronously; it is not async-local state.

## Requirements to carry into guide

One synchronous immutable dataset API with explicit full traversal; exact dataset-version references, source/path document identity and dataset-bound indexes; explicit cross-dataset fusion policy; input-identity bake keys. Transactional snapshots/leases include emitted-event/result packing; detached bounded results; generation-aware further lookup. One resource registry for fresh/load/delta, rollback, duplicate-adoption policy and joined shutdown. Durable descriptors/manifests/current pointer separate from bounded lineage; exclusive namespace lock; crash-safe ordered publication and safe mark/sweep. One immutable terminal operation outcome, owner-thread settlement and listener cleanup; independent shared-job waiters/events. One bounded SSE writer for both HTTP forms. Canonical graph reference traversal, typed validation, explicit delete/projection policy and declared lambda bindings. Strict TS contracts in owning modules; same generated implementation in browser/Goja. Preserve all twelve reported findings and meaningful algorithms/tests. Direct migration, version bump and explicit old-store cleanup; no adapters.

## Decisions still needed

Specify snapshot ID versus dataset ID and build identity separately. Choose frozen-versus-detached records at callback boundary and record order per backend. Choose duplicate resource adoption behavior, result byte/count budgets, retained-generation policy and stale lookup response. Specify exact durable metadata formats and platform fsync/lock implementation. Define operation acceptance arbiter, bounded join and shutdown timeout behavior; a helper name cannot prove race safety. Define graph capability vocabulary and unsupported transform rules; set deterministic model ordering. These are bounded design decisions, not reasons to invent distributed services. Guide should recommend defaults where useful and label them proposals.
