# Runtime source

Edit this directory, then run `pnpm build` from the repository root. The committed
`../assets/rag.js` is generated, readable JavaScript shared by Goja, browsers and
standalone HTML exports. Ordinary Go builds need no JavaScript toolchain.

## Development

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm check
# After runtime changes:
go test ./pkg/ragjs ./pkg/runner ./web
```

`pnpm check` checks types, Biome formatting/lint, generated bytes, and runtime
publication/export/module-graph tests. `pnpm format` formats authored files only.
The build does not minify, uses an ES2020 syntax target, and preserves names.
This is not a polyfill guarantee; Goja tests validate the actual host.

## Module responsibilities

- `api/index.js`: composition and public namespace. Installs built-ins before
  family factories; `define` registers a component then refreshes the public API.
- `api/default-engine.js`: default engine/configuration; explicit engines remain
  available. `workspace.js` and `target.js` handle application conveniences.
- `components/registry.js`: component definitions and ports. `builtins.js`
  explicitly installs built-in components; importing it does not register them.
- `components/markdown.js`, `chunking.js`, `indexes.js`, `hits.js`: algorithms
  and record projections shared by built-ins and execution.
- `graph/graph.js`: the currently coupled builders, compiler and editor. Keep
  the shared reference traversal redesign for RAGWB-009; do not split it with
  cyclic imports merely to reduce a file's line count.
- `engine/engine.js`, `session.js`: build and query execution respectively.
- `engine/records.js`: current lazy persistence and array/view handling. These
  are replacement targets in 009, not the final dataset interface.
- `engine/scope.ts`: synchronous request-scope capture and cancellation contract.
- `engine/decision.js`, `events.js`, `environment.js`: provider mapping, event
  projection and environment timing respectively.
- `evaluation/evals.js`: evaluation and parameter sweeps.
- `export/html.js`: standalone lexical-search HTML generation.
- `core/`: small shared helpers; identity, errors and tokenization are typed.

Imports must be local and acyclic; the runtime test verifies this. Compose
higher-level conveniences at `api/index.js`. Do not import the public namespace
from lower-level modules. State belongs to each evaluated bundle, not a shared
process-level Go singleton.

## Type coverage

Strict TypeScript currently checks these runtime implementations:

- `core/errors.ts`: structured runtime errors.
- `core/identity.ts`: hash primitive, slugs and document IDs.
- `core/text.ts`: stemming/tokenization and options.
- `engine/scope.ts`: cancellation, event sinks, scopes and captured options.

`../type-tests/contracts.ts` exercises positive and negative calls. The other
extracted modules remain JavaScript with `allowJs: true`, `checkJs: false`.
**This is not a fully typed engine or a complete public API declaration.** New
contracts in 009 should be strict TypeScript; migrate their consumers as the
implementation changes. No `@ts-nocheck` or explicit `any` is needed in the typed
foundation. Native/JSON inputs still require runtime validation.

Biome uses a selected correctness ruleset (undeclared identifiers, invalid
construction/assignment, unreachable code, unused imports, duplicate keys and
explicit `any`) instead of applying speculative style rewrites to the runtime.
Generated assets, GUI/kit and ticket investigation scripts are outside its scope.

## Compatibility and tests

Compatibility is not a requirement. Preserve intended behavior, not incidental
object property order. Markdown parity canonicalizes object keys while retaining
array order. RAGWB-009 owns the semantic dataset/ownership redesign and its API
changes; 010 supplies the tooling to implement it clearly.

Node VM tests exercise browser-style publication and exported script execution
with a minimal DOM. They do not establish visual/browser-engine compatibility.
Go tests exercise the actual Goja interpreter and native/JavaScript parity.
